# 工作流操作辅助设计

2026-09-13。用户授权先提交基线，再自主实现、验证和提交，不重复确认。

## 范围

让已选物品、配方、连线和模拟结果成为编辑入口，减少重复搜索、填写及连线。保持玩家对采购、加工方式、留货及续种的决定权；不实现全自动最优方案推荐。

1. 节点侧栏根据产物列出后续种植、加工、出售和已有留货目标。选择后生成并连接，使用自动数量和日期。若原节点唯一普通下游是自动出售，明确显示“接在出售前”，一次操作插入加工节点；不会改变固定数量、手动日期或多来源出售。已有其他普通下游时不主动建立会争抢“剩余全部”的新分支。
2. 加工侧栏展示没有来源或数量不足的材料。数量依据本次模拟已分配原料和完整批数；列出可连接的现有来源，也可一次添加明确数量的买入/已有库存来源。买入必须有已知商店供应和价格；按钮明确数量与日期，只有点击才新增采购。此数量是当前流程快照，后续原料变化重新提示缺口，不静默追加购买。
3. 新节点自动命名，名称随推断物品变化；手动改名永久保留，可恢复自动命名。旧计划只将通用默认名称当自动名称。显式换配方时清除不兼容的旧设备选择，保留台数；导入冲突仍显示问题。
4. 普通下游节点提供“恢复自动数量与日期”，保留配方、设备、续种、留货及在制品设置。在制品与留货节点不显示不适用的快捷恢复。

界面核对补充：加工建议预览每批投入、产出、时间及按当前品质计算的卖价差额。已知增值靠前，未知价格单独说明；排序不代表整月最优方案，不把机器槽位当产量倍率。

## 实现边界

域模块生成带稳定 key 的建议，执行时根据当前计划重新核对 key、兼容性、重复边和环路；每次操作一次撤销，遵守 200 节点 / 500 连线限制。数量短缺与来源缺失分别表达，不能把连线当作已供货，也不能把 3 个槽位当作 3 倍产量。

自动命名只影响展示投影和显式命名模式，不把推断物品 ID 写进用户计划。界面沿用纸色、细边框和现有图标，不另建大面板。原有手动编辑入口全部保留。

## 验证

域测试覆盖源产物筛选、缺少辅料、已分配数量、已有来源、循环/重复拒绝、插入出售前、保护手动设置、命名更新与自定义名、设备兼容、旧计划和容量限制。真实浏览器验证快捷添加、补齐材料、恢复自动、撤销/重做和重新载入。最后构建当前 4323 预览并写报告。
