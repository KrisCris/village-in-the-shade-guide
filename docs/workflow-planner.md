# 生产工作流

**简体中文** | [English](workflow-planner.en.md)

入口：收益规划页的“生产工作流”，路径 `/planner/workflow/`。你在画布上安排买种、种植、加工、留货和出售，工具推算每天的数量、日期、土地、机器和资金。计算和保存都在浏览器里进行，不读取游戏存档。

## 基本用法

1. **买入。** 添加买入节点，选择种子、数量和日期。也可以用快捷入口一次生成“买种 → 种植 → 出售”。
2. **种植。** 把买入连到种植节点。如果种子只对应一种作物，会自动识别，并默认种下全部种子。
3. **加工、出售或留货。** 继续往下连。只有一种可用物品或配方时会自动选上；有多种配方时，自己选要做的产物。
4. **日期。** 默认按材料备齐的时间推算。例如第 1 天种下、生长 5 天，第 6 天收获并投料；加工 1 天的话，第 7 天就能出售或继续加工。关掉自动日期后，可以指定“不早于此日”。
5. **日程。** 底部日程显示每天的买入、播种和收获数量。展开后可以看到：
   - 采购清单；
   - 到账、支出和累计增减；
   - 库存和在制品；
   - 留货目标和下一步操作。

节点的物品、数量和日期默认跟随上游变化，手动设置的值不会被覆盖。出现冲突时只在出问题的节点上说明原因，其他流程照常计算。空节点可以先连好再设置。

## 快速添加下游

选中节点后，侧栏“接下来做什么”会列出当前产物能做的事：种植、已知设备的加工、出售，以及已有的留货目标。点一下就会添加节点并连好，数量和日期自动计算。

加工选项会列出每批的投入、产出、天数，以及按当前品质算的卖价差额，每批增值高的排在前面。这个排序只看单批，没有考虑资金、设备购置、土地、留货和后续加工，不代表整份计划最优。价格未知时不按 0 计算。

如果下游只有一个还没设置的出售节点，新加的种植或加工会插在它前面，并标明“接在现有出售前”，原来的留货连线保留不变。每次快速操作都可以单独撤销。

### 补齐原料

“补齐加工原料”会区分两种情况：原料来源还没连上，或者数量不够。缺口按完整批数计算，留货和已经投进去的原料都会算进去。补齐的方式有两种：连接已有的来源，或者添加一笔指定数量和日期的现有库存或商店买入。

添加的买入是一次性的。之后上游有变化时，不会自动追加购买，而是重新提示缺口。商店没有供应或买价未知的物品，不会生成买入建议。

### 名称和自动值

节点名称默认跟随物品；手动改名后保留，也可以恢复自动命名。切换加工配方时，不兼容的设备型号会改回自动选择，台数保留。“恢复自动数量与日期”只重置数量和日期，不动配方、设备台数、续种和自定义名称。

## 续种与分流

**续种**默认关闭。勾选“收获清田后自动续种”后，每轮保持首轮的规模：先用已有的种子，不够再补买；也可以关掉补买，只用已有种子。补买和播种在日程里分别列出。下一轮在续种范围内或本季结束前收不了，就停止续种，并说明原因。能自然多次收获的作物不会重复消耗种子。

**分流**的顺序是：先满足留货，再分固定数量，最后分配剩余。多个“剩余全部”的去向必须设置不同的顺序或固定数量。未来某天的固定分配会提前锁定物品，不会被“剩余”分支先卖掉。在连线管理里可以看每一批的物品、数量和分配日期。

**留货目标**：新计划会从留货目录生成当季供奉和村长交付目标。删掉的目标不会因为刷新或重新计算而回来。没连来源的目标会标出“尚未安排来源”。设了交付日期的目标，要等物品备齐才一次性交付并扣除；错过日期的物品继续留在库存里，改日期后重新安排。

## 资源与资金

- **土地**：按同一时间占用的最大面积算。续种会复用清空的地；种植时间重叠时需要更多土地。
- **机器**：每个加工节点单独使用自己的机器，默认按来料的完整批数配足台数，也可以换兼容型号或减少台数。每台能同时加工几批来自游戏设备数据，只读显示。容量指配方批数，和每批产量不是一回事。
- **排队**：减少机器后自动排队。节点会显示：
  - 最后一批比配足台数时晚几天；
  - 本期到账少了多少；
  - 加工后比直接卖原料多赚或少赚多少。
- **资金需求**：按每天的执行顺序累计，取最大缺口。顺序是先收已到期的货款，再付购买的钱；新出货的款项要等结算延迟后才到账。不会用未来的货款或这笔购买本身将来的收入来垫付。页面不显示虚构的钱包余额。
- **收支**：本期收支是本期实际到账减去支出。期末之后的加工、出售和到账会继续推演，单独显示最终收支。库存、留货、在制品和待到账分别列出。机器购置和扩建土地的费用不计入，所以这不是完整的投资回报。

## 画布操作

| 操作 | 方式 |
| --- | --- |
| 平移 | 拖动空白处，或按住空格拖动 |
| 缩放 | 滚轮 |
| 框选 | 切换到选择工具后拖动，或按住 Shift 拖动 |
| 切换工具 | H 平移，V 选择 |
| 复制、粘贴、撤销、重做 | Ctrl/Cmd + C、V、Z、Shift + Z |

- 拖动节点时，松手才保存；拖动一组节点只算一次撤销。平移时，选中节点之间的空隙仍算画布，拖空隙只移动视野。
- 右下角小地图可以拖动视野和滚轮缩放。属性面板可以拖动、调宽和关闭，日程展开后可以调高。右上角可以进入专注模式。
- 点击日程里的操作会跳到对应节点。复制的节点使用新编号，只复制选区内部的连线。

## 计划文件

文件菜单可以新建、导入和导出计划。导入旧版计划时，会保留手动设置的日期、数量、机器型号和台数，可以逐个恢复为自动。旧节点手填的容量会删除，改用游戏数据。

浏览器里的旧计划第一次升级时，会尽量保留一份升级前的备份，可以在文件菜单导出。存储空间不足时，原计划仍然可以读取。

## 计算范围

- **日期**：每月 28 天，每年 112 天。购买和续种范围 1–112 天。加工时长按 24 小时向上取整，最早第二天完成。
- **到账**：默认延迟 1 天，可以设为 0–7 天。
- **已有资源**：已有库存不计历史成本。已有作物和在制品可以填写剩余天数。
- **数据来源**：商店供应、年份和季节使用站内资料；解锁条件请自己在游戏里确认。
- **不推算的内容**：未核实的跨季转化、多阶段生长、缺少生长时间的作物，以及天气、肥料、体力和混合品质。跨季生长也不模拟。
- **推演上限**：后续事件最多推演到第 100 年，超出会提示，未完成的状态保留。
- **规模限制**：一份计划最多 200 个节点、500 条连线，每个节点最多 10000 台机器。

## 维护

设备容量数据在 `data/sources/game-machine-capacities.json`，由 `tools/extract-machine-capacities.py --game-dir <游戏目录> --output <审阅文件>` 从游戏文件提取。依据是 `gimmick.dat` 第一组 `settingArg`，以及原生 `GimmickProcessPushItem` 的槽位分支，不按设备名称猜测。文件里记录了原表和可执行文件的 SHA-256。

当前构建 25311578 有 29 种配方加工设备：13 种改良设备有 3 个槽位，其余 16 种只有 1 个槽位（包括蜂箱、树液采集器和养蚕箱）。容量未知的设备不会默认为 1，也不会安排加工，而是提示“数据尚未核实”。工作台、炉灶、洒水器等设备不属于这种配方加工模型。

计划文件格式是 version 1，用 `planningMode: intent` 和自动／手动字段区分。

| 位置 | 作用 |
| --- | --- |
| `src/domain/workflow/intent.ts` | 推断物品和兼容选项 |
| `src/domain/workflow/intentSimulation.ts` | 材料分配、排期、资源和收支 |
| `src/domain/workflowEditor.ts` | 创建和迁移计划 |
| `src/components/workflow/` | 画布、节点和日程 |

目前还没有自动推荐器。以后的推荐器应生成同样格式的计划，再交给模拟器验证。

改动后运行 `npm run verify` 和 `npm run check:build`。在生产预览里检查画布操作。
