# 农场生产工作流

入口：收益规划页的「生产工作流」，路径 `/planner/workflow/`。计算和保存都在浏览器内，不读取游戏存档。

## 从玩家的安排出发

1. 添加买入节点，选择种子、数量和购买日期；也可以从快捷入口生成买种 → 种植 → 出售。
2. 将买入连接到种植。新种植节点自动识别唯一作物，种下全部种子；不需要先填写田地或钱包。
3. 连接加工、出售或留货节点。只有一种兼容物品或配方时自动推断；有多种配方时选择要做的产物。
4. 日期默认按材料齐备时间推算。例如第 1 天种下、生长 5 天，第 6 天收获并投料；加工 1 天，第 7 天即可出售或继续加工。关闭自动日期后可以指定“不早于此日”。
5. 底部日程显示每天买入、播种、收获的实际数量。展开后查看采购清单、到账与支出、相对期初累计增减、库存、在制品、留货目标和下一次操作。

新节点的物品推断、数量和日期始终跟随上游。手动选择保留；发生冲突时在该节点解释原因，不使其他流程停算。空节点可以先连接再配置。

## 减少重复设置

选中节点后，侧栏「接下来做什么」只列出当前产物可用的种植、已知设备加工、出售和已有留货目标，支持搜索。点击后添加并连好节点，数量与日期自动计算。种子只有一种对应作物时，快捷种植不固化作物；更换种子会继续更新作物、自动名称和下游出售。

加工选项预先列出每批投入、产出、天数及按当前品质计算的卖价差额，已知每批增值较高的选项靠前。该排序不考虑整月资金、设备购置、土地、留货和后续加工机会，不能等同于整份计划的最优收益；未知价格不按零计算。

若唯一普通下游是未指定物品、自动数量和日期的出售节点，种植/加工选项会标明「接在现有出售前」，一次插入并重连，保留原有留货连线。其他手动分流或多来源出售保持原样，使用原有手动编辑入口调整。每项辅助操作都对应一次撤销。

「补齐加工原料」区分未连接来源和数量不足，按已分配原料的完整批数计算还缺多少；留货、已加工消耗及每批投入数量都计入。可以连接已有来源，也可明确添加指定数量和日期的已有库存或已知商店买入。按钮显示数量、日期与已知支出；这些根节点是一次安排，不会在以后修改上游时静默追加购买，缺口会重新提示。无已知商店供应或买价时不生成买入建议；已有在制品不要求重新准备已投入的原料。

新节点名称自动跟随物品，手动改名后保留，可恢复自动命名。显式切换加工配方时，不兼容的旧设备型号恢复为自动选择，台数仍保留。普通下游节点可一次「恢复自动数量与日期」，不更改配方、设备台数、续种或自定义名称。

## 续种与分流

续种默认关闭。勾选「收获清田后自动续种」后，保持首轮规模，优先使用已有种子，再补买缺口；可关闭补买，只用已有种子。每次补买和播种分别列入日程。后续一轮无法在选择的续种范围及本季内收获时，停止续种并解释原因。天然多次结果不重复消耗种子。

留货优先，其次是固定分配数量，最后分配剩余原料。多个“剩余全部”去向必须设置不同分流顺序或固定数量，系统不会按随机编号抢货。未来的固定分配会先锁定物品，避免被剩余分支卖掉。连线管理可查看每批的物品、数量和分配日期。

新计划从留货目录生成当季供奉、村长交付目标，可删除，刷新和计算不会补回。未连接的目标显示尚未安排来源。指定交付日期后，备齐才会一次性交付并扣除；错过日期的物品继续留存，需要修改日期后重新安排。

## 资源与资金

- 土地按最大同时占地推算。续种复用清空的土地，重叠种植增加需求。
- 每个加工节点独立使用机器。默认按来料完整批数自动配足；可以选兼容型号或减少台数。每台同时加工批数来自游戏设备数据，只读展示；切换型号自动重算需求和排队日期。容量是配方批数，不能与每批产量混用。
- 减少机器会自动排队。节点展示相对自动配足时末批延后天数、本期到账差额，以及加工产物相对原料直接出售的价值变化。
- 资源数量表示需求。机器购置、土地扩建费用另计，不能将原料经营收支当作完整资产回报。
- 资金需求取每日执行顺序中最大的累计资金缺口。已到期货款先到账，购买先支出，产生的出货款依结算延迟到账；不会用未来货款或一笔购买自身尚未产生的销售款融资。不展示虚构的钱包余额。
- 本期收支是本期实际到账减支出。期末之后的加工、出售和到账继续推演，并单独展示最终收支。库存、留货、在制品及待到账分别列出。

## 编辑与备份

左键拖动空白处平移，滚轮缩放；点击框选或按住 Shift 拖动框选。H / V 切换工具，空格临时平移。支持 Ctrl/Cmd + C、V、Z、Shift Z，以及删除、重做。每次拖动在松手时保存，整组拖动对应一次撤销。

平移模式和空格临时平移时，已选节点之间的空隙仍属于画布；拖动空隙只移动视野，拖动节点卡片才移动选中的节点。右下角小地图支持拖动视野和滚轮缩放，其 SVG 尺寸与交互坐标使用同一组数值。

属性面板可拖动、调整宽度和关闭；展开日程后可调整高度。右上角可进入专注模式。点击日程操作会定位对应节点。副本使用新编号，只复制选区内部连线。

计划文件菜单可新建、导入、导出。旧版计划导入时保留手动日期、数量、机器型号和台数，可逐个恢复自动；移除旧节点手填的容量，改用游戏数据。浏览器内旧计划首次升级时尽量保留独立备份，文件菜单可导出升级前备份；存储空间不足时仍可读取原计划。

## 计算范围与维护

每月 28 天，每年 112 天。购买 / 续种范围 1–112 天；加工时长按 24 小时向上取整，最早次日完成。到账默认延迟 1 天，可改 0–7 天。已有库存不扣历史成本，已有作物 / 在制品可填写剩余天数。

商店供应、年份、季节使用现有资料；解锁条件需玩家核对。未核实的跨季转化、多阶段生长、缺少生长时间的作物，以及天气、肥料、体力、混合品质继承不自动推断。跨季生长目前不模拟。后续事件最多推演至第 100 年，超限明确提示并保留未完成状态。

计划格式保留版本 1，新增 `planningMode: intent` 和自动 / 手动字段；旧的直接计算接口兼容保留，普通页面全部使用新模型。编辑器限制 200 个节点和 500 条连线；节点机器台数上限 10000，容量不属于玩家配置。

设备容量见 `data/sources/game-machine-capacities.json`，由 `tools/extract-machine-capacities.py --game-dir <游戏目录> --output <审阅文件>` 只读提取。当前构建 24969282 的 29 种配方加工设备中，13 种改良设备有 3 槽，其余 16 种为 1 槽（含蜂箱、树液采集器、养蚕箱）。依据 `gimmick.dat` 的第一组 `settingArg` 和原生 `GimmickProcessPushItem` 的槽位分支，记录原表及执行文件 SHA-256；不通过设备名称猜测。未知容量不默认当作 1，不安排加工并提示数据尚未核实。工作台、炉灶、洒水器等不属于这一配方加工模型。

代码：`src/domain/workflow/intent.ts` 推断物品和兼容选项；`intentSimulation.ts` 计算材料分配、排期、资源与收支；`workflowEditor.ts` 创建和迁移计划；`src/components/workflow/` 呈现画布、节点及日程。推荐器尚未实现，之后可以生成同一格式的计划再交给模拟器验证。

验证：`npm run verify`；`npm run check:build`。浏览器交互检查记录于忽略目录 `output/playwright/`。
