# 内容覆盖与限制

**简体中文** | [English](content-coverage.en.md)

游戏快照：Steam 构建 `25640656`（1.30 版本）。对照目录：[AppMedia](https://appmedia.jp/honogurashi/)（只用来对照选题）。

## 已覆盖

- **结构化数据**：物品、作物、机械加工、制作与料理、鱼类、居民，以及已解析的商店、交付、解锁和家畜关系。每个条目都有双向详情：物品能查到配方、机器和商店，反过来也一样。
- **规划工具**：加工增值、从种子开始的整体收益、生产工作流。
- **1.30 更新**：主角生日（解锁条件、林的来信、14 位居民的生日礼物）、播种机的购买条件和各级播种范围、卫浴设备家具，以及官方更新说明里的其他改动。“？？？”事件只写出现条件，不写剧情。
- **原创攻略**：四季留货、钓点、采石场、生日送礼、外观获取、祠堂技能、收集地图、钓鱼和料理准备、夜间准备、怪异出现条件与对策、深夜出没的妖怪、特殊种植、狩猎、家畜、建筑与温室、帮忙券与推进目标、咒物与心和活力上限等。
- **存档编辑器**：见 [存档编辑器说明](save-editor.md)。
- **英文版**：物品、角色、地点、任务等名称和说明直接用游戏 1.30 的官方英文；界面和攻略正文是本站自己的英译，用词跟游戏一致。AppMedia 待补充主题的标题和提纲另有英文对照（`data/sources/guide-translations.en.json`）。

关键数值和条件以 `data/generated/`、`data/sources/game-*.json` 为依据。钓点名称的推导见 [`data-evidence/fishing-locations.md`](data-evidence/fishing-locations.md)。

## 尚未完整覆盖

- AppMedia 的 116 个主题都已映射到站内页面。`npm run content:check` 只检查映射是否齐全、链接是否有效，不保证每个主题都有完整正文。
- 本站攻略已经写到的主题（家畜解锁、品评会、钓鱼、采矿、各章节主线等）直接跳转到对应攻略，不再在攻略一览里重复列出；太基础或与攻略无关的主题（存档、多人、注视、口哨种类、游戏模式、交流板等）跳回攻略一览。规则在 `src/data/guideContent.ts` 的 `guideTarget` 和 `retiredGuideTitles`。
- 攻略一览的“待补充的主题”是还只有提纲的页面，例如节庆活动。
- 攻略不是日文站点的逐篇翻译，也不覆盖全部剧情分支、随机任务和隐藏条件。
- 地图只标出已解析的点位，不代表这些物品在任何进度下都能取得。
- 生日、礼物偏好和部分食谱的传授方式有游戏数据依据；餐厅学习菜谱所需次数没有核实，不能统一写成“吃 3 次”。
- 建筑订单的前置条件、工期和扩地条件已从 `construction.dat` 和相关脚本解析（`tools/extract-construction.py`）；鸡舍、畜舍、马厩和铁砧另有一个 1–4 的等级值，含义未明，可能是额外条件。温室要求的品牌品质怎样取得也没有核实。
- 委托的随机抽取方式没有完整解析。村里和附加农地的夜间闪光点物品池已从 `placementitem.dat` 解析（`data/sources/game-curse-items.json`）。泥土种子抽哪种作物、何时变成被诅咒的作物或巨大作物写在游戏程序里，已按 `village.exe` 的种植和生长代码整理进同一文件。不能从已解析的个别点位推断整个随机池；随机交付候选不代表固定委托。
- 怪异页的条件、打法、奖励和地图位置来自 `data/sources/game-anomalies.json`（`tools/extract-anomalies.py`）：脚本、`gimmick.dat` 和村庄地图的锚点与放置物。页面还收录不在深夜轮换里的夜间事件：黏黏妖、巨大兔、鲜红的手机、日本人偶、泥田坊、妖怪蔬菜与妖怪鱼、龙神渊的池主和牛鬼。插图由 `tools/extract-anomaly-art.py` 和 `tools/render-anomaly-art.mjs` 从游戏动画模型渲染。写在游戏程序里的部分（同一晚多种怪异都满足条件时的权重、蛟和不倒翁圆石的选点几率）页面不写具体数值。
- 深夜妖怪页的出现区域、数量、伤害和掉落来自 `data/sources/game-night-monsters.json`（`tools/extract-night-monsters.py`）：`placementhorror.dat`、村庄地图格子上的刷新表编号、`creature.dat`、`attack.dat` 和各妖怪的 `ai_creature_horror_*` 脚本。附身草丛和迷途森林不在村庄小地图上，页面只用文字说明。同一区域里五种通用妖怪各抽到几只由游戏程序随机决定，页面只写总数。剧情里的妖怪（以津真天、鵺皮、人影、斑点狗、木灵）只列出章节和地点。
- 程序生成的“用途”只覆盖已解析的关系，不等于游戏里的全部用途。
- 品质倍率下的金额带小数，是估算值；游戏最终如何取整没有完全核实。
- 收益排行基于页面列出的生长时间、加工时长和种子供应等假设，没有考虑天气、技能、机器排队和玩家行动安排，不等于最优解。

## 写作原则

- 保留证据和不确定性。有价格记录不等于商店有卖；一次随机交付不等于固定需求。
- 没核实的规则写明“未核实”，不要猜。
- 自动检查（`npm run verify`）只能证明数据和页面自洽，不能代替游戏内验证。
