# 内容覆盖与限制

**简体中文** | [English](content-coverage.en.md)

游戏快照：Steam 构建 `25311578`。对照目录：[AppMedia](https://appmedia.jp/honogurashi/)（只用来对照选题）。

## 已覆盖

- **结构化数据**：物品、作物、机械加工、制作与料理、鱼类、居民，以及已解析的商店、交付、解锁和家畜关系。每个条目都有双向详情：物品能查到配方、机器和商店，反过来也一样。
- **规划工具**：加工增值、从种子开始的整体收益、生产工作流。
- **原创攻略**：四季留货、钓点、采石场、生日送礼、外观获取、祠堂技能、收集地图、钓鱼和料理准备、夜间准备、特殊种植、狩猎、家畜、帮忙券与推进目标等。
- **存档编辑器**：见 [存档编辑器说明](save-editor.md)。

关键数值和条件以 `data/generated/`、`data/sources/game-*.json` 为依据。钓点名称的推导见 [`data-evidence/fishing-locations.md`](data-evidence/fishing-locations.md)。

## 尚未完整覆盖

- AppMedia 的 116 个主题都已映射到站内页面。`npm run content:check` 只检查映射是否齐全、链接是否有效，不保证每个主题都有完整正文。
- 本站攻略已经写到的主题（家畜解锁、品评会、钓鱼、采矿、各章节主线等）直接跳转到对应攻略，不再在攻略一览里重复列出；太基础或与攻略无关的主题（存档、多人、注视、口哨种类、游戏模式、交流板等）跳回攻略一览。规则在 `src/data/guideContent.ts` 的 `guideTarget` 和 `retiredGuideTitles`。
- 攻略一览的“待补充的主题”是还只有提纲的页面，例如怪异、节庆活动、建筑扩建和咒物。
- 攻略不是日文站点的逐篇翻译，也不覆盖全部剧情分支、随机任务和隐藏条件。
- 地图只标出已解析的点位，不代表这些物品在任何进度下都能取得。
- 生日、礼物偏好和部分食谱的传授方式有游戏数据依据；餐厅学习菜谱所需次数没有核实，不能统一写成“吃 3 次”。
- 建筑的解锁年份和事件条件、委托的随机抽取方式、夜间拾取池和泥种子转换池都没有完整解析。不能从已解析的个别点位推断整个随机池；随机交付候选不代表固定委托。
- 程序生成的“用途”只覆盖已解析的关系，不等于游戏里的全部用途。
- 品质倍率下的金额带小数，是估算值；游戏最终如何取整没有完全核实。
- 收益排行基于页面列出的生长时间、加工时长和种子供应等假设，没有考虑天气、技能、机器排队和玩家行动安排，不等于最优解。

## 写作原则

- 保留证据和不确定性。有价格记录不等于商店有卖；一次随机交付不等于固定需求。
- 没核实的规则写明“未核实”，不要猜。
- 自动检查（`npm run verify`）只能证明数据和页面自洽，不能代替游戏内验证。
