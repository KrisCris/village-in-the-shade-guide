# 存档编辑器

**简体中文** | [English](save-editor.en.md)

网页入口：`/save-editor/`。存档在浏览器里读取和修改，导出为新文件，不会上传。

文档分三部分：

1. 使用说明：给玩家看。
2. 存档格式：给维护者看，记录已核实的结构。
3. 编辑规则：说明各个功能按什么游戏规则写入存档。

## 使用说明

### 找到存档

```
%APPDATA%\Nippon Ichi Software, Inc\Honogurashinoniwa\<SteamID>\
  save.001 … save.005   槽位存档，每个 3 MiB
  save.lst              读取界面的摘要缓存
  .systemsave           全局设置和槽位索引
```

游戏里只有 3 个槽位，文件却有 5 个，因为每个槽位轮流写入不同文件。要确定某个槽位当前用的是哪个文件，在编辑器的“如何确认当前使用哪个存档文件？”里读取同目录的 `.systemsave`，页面会显示三个槽位各自对应的文件。也可以直接按修改时间判断，选最新的那个。

浏览器不能直接打开 AppData 目录。页面提供可复制的路径，粘贴到文件选择窗口的地址栏即可。

### 编辑和导出

1. **备份。** 先复制整个存档目录。
2. **读取。** 选择存档文件，按分类修改。分类包括基础信息、玩家、物品、畜牧、NPC、地图、任务、收集与解锁。右上角的“完整字段树”能按名称或路径找到任意字段。其他标签页已有的字段在树里按同一类型显示和校验，例如浮点数不会显示成整数位。
3. **核对。** 导出前，预览按标签页分组列出全部修改，可以逐项撤销。地图修改按操作和对象合并成一行，例如“放置 · 户外石砖地板 · 3 个”，可以整组撤销。物品移动或互换显示为一行，撤销时一起还原。给已经湿润的田浇水不算修改，不会出现在列表里。超出范围的数值会在输入框和预览里标红，改正之前不能下载。修改金钱、满好感或品牌物品时，页面会提示可能影响成就，需要确认后才能导出。
4. **替换。** 下载修改后的副本，关闭游戏后替换原文件。

编辑草稿保存在当前浏览器会话里。离开页面再回来，只要重新选的是同一个文件（按 SHA-256 核对），草稿就会恢复。

读取界面的玩家名、日期和时长来自 `save.lst`。编辑器不改这个文件，所以替换后读取界面可能还显示旧值，进入游戏后才是新值。

### 可以改什么

| 分类 | 内容 |
| --- | --- |
| 基础信息 | 玩家名、犬名、金钱、供奉金、游戏日期和时刻、实际游玩时长、天气 |
| 玩家 | 生命、体力、外观和配色、发色 |
| 物品 | 背包、工具栏、出货箱、收纳箱、加工设备和特殊容器；增删物品、改数量和品质、拖放移动；升级工具；按交付或技能需求补齐材料 |
| 畜牧 | 按畜舍、禽舍、马棚分组；改名字、好感、心情、喂食，新增动物，在栏位间移动 |
| NPC | 好感度 |
| 地图 | 农场和室内的作物、地形、设施、建筑和家具；见下方“地图编辑” |
| 任务 | 已有任务的显示状态和清单勾选 |
| 收集与解锁 | 图鉴、技能树、配方、外观、村长交付目录、品牌名 |

### 地图编辑

- **视图**：滚轮缩放；中键、平移工具或按住空格拖动可以平移。小地图用来定位，“季节与图层”可以切换季节预览、成熟预览和地形禁放区。季节和成熟预览只影响画面，不改存档。
- **选择**：点击选中，拖动框选。框选后会按种类列出选中的东西，可以只保留某一类或只保留空地，再对这些格子批量种植、铺地板、浇水、翻地或清理。
- **笔刷**：种植、清除、浇水、耕地、田垄、水田。按住拖动可以连续编辑，一笔对应一次撤销。
- **放置**：从目录选设施、建筑、地板或家具，按 R 旋转。地板可以按住拖动连续铺设。选中已有物体后可以移动、旋转、升级或删除。
- **触屏**：单指框选或使用笔刷，双指平移。笔刷在松手时提交；途中加入第二根手指会取消这一笔。
- **布局文件**：可以把地图编辑导出为 JSON，再导入到其他存档。导入时会按目标存档重新检查位置。

### 不做的事

- 不补发奖励，不触发剧情事件，不改成就计数。
- 不更新 `save.lst`。
- 不能任意跳转剧情；任务页只改已有任务的状态。
- 马棚和狗窝只能改属性，不能新增动物或跨位置安置。
- 发色只预览纹理采样，不渲染完整角色。
- 编辑器只做了离线结构验证，没有在游戏里验证每一种修改。替换前一定要备份。

## 存档格式

格式在作者的 6 个测试存档（`save.001`–`save.005` 和 `.systemsave`）上验证过：都能完整解析，不修改时重新写出的文件和原文件逐字节相同。

### YKCMP 容器

小端序：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `0x00` | char[8] | `YKCMP_V1` |
| `0x08` | u32 | 压缩类型：槽位存档和 `.systemsave` 是 `8`（裸 LZ4 block），`save.lst` 是 `4`（YKCMP 自己的 LZ77，不支持） |
| `0x0c` | u32 | 压缩数据结束偏移 |
| `0x10` | u32 | 解压后长度，槽位存档为 `0x1400000`（20 MiB） |
| `0x14` | … | LZ4 block，没有 frame 和长度字段 |

文件长度固定，压缩数据后面的字节游戏不读，导出时保持原长度。

### SER 节点树

解压后的数据：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `0x00` | char[4] | `SER\0` |
| `0x04` | u32 | 保留，样本中都是 0 |
| `0x08` | u32 | 已使用长度（头 + 节点树 + 名称表） |
| `0x0c` | u32 | 名称表偏移 |
| `0x10` | … | 根节点 `SAVEDATA` 或 `SYSTEMSAVEDATA` |

名称表是一串 `\0` 结尾的字符串，字段名就是游戏的 C++ 成员名（`money_`、`loveRate_` 等）。

每个节点是 `[tag u8][nameOffset u32][size u32] (+ [ref u32]) [payload]`。只有 tag 1、3、4 带 `ref`，而且 `ref` 不计入 `size`。

| tag | 类型 | payload | ref |
| --- | --- | --- | --- |
| 0 | scalar | 1、2、4 或 8 字节数值 | — |
| 1 | blob | `ref` 个定长元素 | 元素个数 |
| 2 | object | 子节点 | — |
| 3 | list | 子节点；Map 的子节点是 `0k`/`0v`/`1k`/`1v`…，共 `ref × 2` 个 | 元素个数 |
| 4 | pointer | 空，或一个名为 `p` 的子节点；多态指针前面多一个 `className` 字符串 | 文件偏移 |
| 5 | string | `[长度 u32][UTF-8][\0]` | — |

指针的 `ref` 是文件偏移。`ref` 等于节点自身偏移，表示指针拥有后面的对象；`0xFFFFFFFF` 是空指针；其他值是引用别处已序列化的节点。样本里这种引用只有一个：`pConstructionStatus_/pStatus_` 指向 `gimmickList_` 中的一项。

**任何长度变化都会让后面所有节点的偏移移动，所有指针的 `ref` 都要重写。** `serializeSer` 会重排偏移并改写指针，因此名字可以改成任意长度。整体重建列表时，保留下来的节点继续沿用原偏移映射，外部引用仍指向原对象；新克隆的节点没有偏移身份。blob 的 `ref` 无法从子节点推出，重建时必须原样保留：写成 0，游戏会把数组读成空的。加工设备的 `timeValue_`、`createTime_` 都是 blob，丢失元素个数后所有加工进度都会清零。新名称会追加到名称表末尾。

### 主要字段

```
SAVEDATA
├── playTime_                         date_/hour_/minute_/second_/frame_/wholeframe_
├── flags_/flags_                     blob，1563 × 8 字节的标记位
├── gameValues_                       Map，value 是 {min_, max_, this->value_}
├── gameTime_/second_                 i64，游戏内累计秒数
├── money_ / offeringMoney_           i64
├── pWeatherData_/dataID              天气表 ID
├── pPlayerStatus_/p                  名字、犬名、hp_、st_、外观 ID、配色、工具范围
├── inventoryItemList_ / toolItemList_   物品指针列表，空格是空指针
├── shippingBoxItemList_              出货箱
├── gimmickList_                      地图上的全部物体；带 itemList_ 的是容器
├── livestockList_                    动物
├── npcStatusList_                    NPC 好感和日程
├── questMap_ / encyclopediaReleaseMap_ / skills_ / bundleList_
├── brandCropsNameMap_                Map：收获物物品 ID → 品牌名
└── statusUniqueIDGenerator_/idSeed_  唯一 ID 生成器
```

所有物品对象的结构都一样，不管在背包、工具栏还是容器里，字段包括 `uniqueID_`、`pData_/dataID`、`stackCount_`、`rank_`、`qualityUpValue_`。物品对象里没有指针，所以新物品可以克隆现有对象再改字段，`uniqueID_` 从 `idSeed_` 顺序分配。

### 游戏常量

数值来自 `gamedefine.dat`：

| 项目 | 值 |
| --- | --- |
| 生命 | 初始 12，上限 40，每颗心 4 点，最多 10 颗 |
| 体力 | 初始 190，上限 950，每段 190，最多 5 段 |
| NPC 好感 | 各级上限 100、300、600、1000、1500、2100 |
| 物品品质 | 0 普通、1 铜、2 银、3 金、4 品牌 |
| 数量、金钱 | 每格最多 999；金钱最多 99,999,999 |

`qualityUpValue_` 的含义未查明，编辑器保留原值。

## 编辑规则

下面的规则来自游戏表和原生代码。原生函数地址等研究记录可以用 `tools/save-probes/` 复查。

### 时间

- `gameTime_/second_`：一天 86400 秒，每季 28 天，每年 4 季，从春季开始；一天从 07:00 算起，凌晨 0:00–6:59 仍属于前一个游戏日。换算使用 BigInt。
- `playTime_` 是实际游玩计时器，和游戏日期互不换算。修改时清零 `frame_` 的不足一秒部分，保留 `wholeframe_`。小时最多 9999。

### 玩家与工具

- 降低生命或体力上限时，当前值会一起降低；导出前会再检查一遍。
- 工具等级以 `item.dat` 为准（1–5）。存档保存的是玩家当前选择的范围，只有更换同类工具的等级时才同步范围。
- 发色向量是对纹理的 HSV 调整（H 相加，S、V 相乘），`(0,1,1)` 表示原色。预览按同一方式对实际发型纹理取样。
- 外观类物品（前发、后发、服装、围巾、饰品、包）进入背包时，游戏会改为解锁对应款式，所以物品选择器不提供这几类。

### 容器与加工

- 收纳箱和设备的格子在 `gimmickList_` 各项的 `itemList_` 里。出货箱用根部的 `shippingBoxItemList_`；列表为空时也显示 30 格，添加物品时才扩展列表。
- 配方加工设备：`timeValue_` 是开始时刻，`createTime_` 是持续秒数，`itemID0..2` 和 `itemVal0..2` 是产物和数量。改良设备最多 3 项任务。“立即完成”只改开始时刻；新增加工使用合法配方，不扣除背包材料。
- 树液采集器依附所在的树，从第一个物品模板产出 1 个产物；只能推进计时，不能任意加配方。畜产品回收机只显示和修改已收集的物品。
- 桌面摆放设施和妖怪置物架的内容和摆放对象互相关联，编辑器只显示，摆放和取出请在游戏里操作。
- 按类别批量操作时，只往支持所选配方的空栏位添加任务，已有任务保持不变。

### 畜牧

- 每颗心 300 或 400 点（由种类和运行时特性决定），最多 5 颗；狗是 400 点。心情 0–255，喂食是开关。
- 可用栏位由建筑决定。新增动物需要存档里至少有一只普通动物作为结构模板。新增时会按目标品种设置纹理和包围盒。成年动物的成长值写成幼崽长大所需天数，和游戏存档一致（鸡 5、鸭 7、羊 10、牛 14）；好感、心情和临时状态从零开始。马棚的三个位置是马棚模型（`arc_1201`）上的挂点 `posIN01`–`posIN03`，坐标等于马棚位置加偏移 (−2, −33)、(−102, −121)、(−192, −211)，镜像马棚的 x 取反；地图上移动马棚时，马跟着移动。
- 升级畜舍时，动物留在原建筑，尽量保持原栏位顺序；位置不够时报错，不会把动物偷偷移到别的建筑。拆除畜舍时，动物需要有其他空栏可以去，否则拒绝导出。有马时不能拆马厩。

### 任务、解锁与交付

- 任务：`checkLevel_` 大于清单阈值时算作勾选。状态 0 隐藏、2 显示、3 完成，游戏存档里不出现 1。勾满清单时，普通任务改为 3；村规（`CHAIN_VILLAGE_RULES_*`）和村民求助任务（各村民的 `*_01`）在游戏里勾满后仍是 2，编辑器照此处理。只改任务本身，不碰剧情标记。
- 图鉴：`encyclopediaReleaseMap_` 记录物品 ID，值固定为 1。带 `ITEM_FEATURE_NOT_PUBLISH_ENCYCLOPEDIA`（itemfeature 8）的 76 个物品不在游戏图鉴里显示，包括建筑奖励、配方书、工具基底和演示用道具，编辑器也不列出它们；存档里已有的这类记录原样保留。
- 技能树：解锁会补齐前置节点，锁定会联动后继节点，`skills_` 和标记位同步更新。神龛修缮等级不自动修改。学习成本的六种材料依次是勾玉、雨勾玉、双子勾玉、小孩勾玉、铜镜、剑（物品 650000、650010、650020、650030、650040、650060），“补齐材料”按这个顺序放入背包。
- 村长交付：交付材料按 `itemId u32、rank u32、count u32` 读取，高品质要求是 rank 4。编辑器只修改剩余数量；全部交付后设置该册的完成标记，但不触发交付事件或补发奖励。可以“留最后一件”，到游戏里完成最后一次交付。“开放村长家的交付目录”只设置 `GAME_FLAG_STORY_02_022`。

### 地图

- **场景**：64 个室外和室内场景，地形来自 YMWR，格距 45 单位，格 ID 为 `round(y/45)*1000000 + round(x/45) + 1`。只有地面掩码允许的格子可以编辑，田地扩张另外检查标记 147/148。
- **作物**：可用土壤以 crops 表为准，稻米和山葵只能种在水田。成长阶段写入 `growth_` 和 `formID_`，`formID_` 表示正常、枯萎、再收获、树桩等状态，不是动画编号。`growth_` 是 `{min_, max_, this->value_}` 区间，游戏让 `min_` 为 0、`max_` 为当前形态最后一个阈值，读档时把 `value_` 截到 `max_`。所以改形态或成长值时要同时改 `max_`，否则显示的阶段和游戏里不一致。剩余天数按每天 100 成长点估算，不考虑季节、肥料和浇水的影响。
- **浇水**：只给耕地和田垄浇水，水田不需要浇水。
- **设施**：碰撞使用 FAD 碰撞区域，相邻的单格菱形可以共边。陷阱、捕蟹笼、墙面挂件等特殊设施按各自的地形类别放置。水田里不能放普通设施（地毯也不行），稻草人除外。
- **包围盒**：新放置物体的 `baseAABB_` 取 FAD 初始帧（有朝向的物体取对应朝向帧）中带贴图节点四边形的并集，镜像物体左右翻转。数值由 `tools/extract-map-art.py` 写入 `game-map-rules.json` 的 `aabb`。
- **地板**：不能铺在作物、树木或设施下面，要先清除。石砖类地板（脚本 `gimmick_cobblestones`）的 `statusValueMap_` 要写入 `se = 1`，否则进游戏时会再播一次铺设音效。可以铺在耕地上，耕地会恢复为平地。
- **建筑**：建造时会清空占地范围内的作物、地板和普通设施。编号从空闲槽位分配，升级时保留唯一 ID；室内物品按原楼层和相对位置移到新房间。固定场景物体和自宅不能删除，自宅只能原地升级。出货箱是场景固定摆设，只显示，不能移动。
- **室内**：住宅等级按标记 140–142 选择房型，标记 143 开放地下室。灯光和地板遮罩不当作普通家具绘制。
- **布局文件**：JSON version 1，只保存场景、格子、模板 ID 和编辑操作，不包含存档内容。导入时会在目标存档里重新检查模板、边界、占地和区域开放状态；移动操作找不到源设施时拒绝导入。

## 维护

### 代码结构

| 位置 | 作用 |
| --- | --- |
| `src/lib/saveEditor.ts` | YKCMP 和 LZ4 编解码 |
| `src/lib/ser.ts` | SER 解析和序列化（重排偏移、改写指针） |
| `src/lib/saveModel.ts` | 字段分类、改动收集和导出 |
| `src/lib/saveItems.ts`、`saveInventory.ts`、`saveMachines.ts`、`saveTools.ts` | 物品、容器、加工设备和工具 |
| `src/lib/saveAnimals.ts`、`saveQuests.ts`、`saveProgress.ts`、`saveShrine.ts`、`saveDeliveries.ts` | 畜牧、任务、解锁、技能树和交付 |
| `src/lib/saveMap*.ts` | 地图场景、几何、房间、放置规则和编辑 |
| `src/lib/saveSession.ts` | 浏览器草稿恢复 |
| `src/lib/saveValidation.ts` | 导出前检查 |
| `src/components/save/` | 编辑器界面 |
| `tools/save_format.py` | 不依赖第三方库的 Python 参考实现，用来独立核对 |

编辑器使用的目录数据在 `data/sources/game-save-*.json` 和 `game-map-*.json`，由 `tools/extract-save-*.py` 和 `tools/extract-map-art.py` 从游戏文件提取（见 [游戏数据维护](data-extraction.md)）。名称和图标查询表 `public/save-editor-names.json` 由 `npm run build:data` 生成。

回归测试用的是作者的测试存档，覆盖逐字节往返、长度变化后的指针一致性、字段读写和各类编辑规则。存档以加密形式提交，CI 会解密使用；本地没有存档时，这部分测试会跳过。见 [tests/gamesave/README.md](../tests/gamesave/README.md)。

修改编辑逻辑后，至少要做以下检查：

1. 在生产预览里实际编辑一次，然后导出。
2. 用编辑器重新读取导出的文件，确认修改都在。
3. 用 `tools/save_format.py` 独立解析导出的文件。

测试存档只读，编辑后的副本放在被忽略的 `output/` 下。不要把修改过的存档放进游戏存档目录做测试，除非你已经备份。
