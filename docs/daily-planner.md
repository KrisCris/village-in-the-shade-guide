# 每日规划

**简体中文** | [English](daily-planner.en.md)

入口：顶部导航的“每日规划”，或收益规划页里的链接，路径 `/planner/today/`。选一个槽位存档（`save.001`–`save.005`），页面列出今天要做的事。存档只在浏览器里读取，不会上传，也不会被修改。

## 页面内容

最上面是存档的日期、天气、持有金钱和本季进度条（28 格，标出今天）。下面一排数字卡片是各部分的摘要：还没做完的待办、今天能交的交付、今天能补的图鉴、要加造的设备、空着的农田格子和畜舍空位，点一下跳到对应的部分。往下滚动时，部分目录和“地图”按钮固定在页面顶部。

页面从上到下分成七部分：

- **今日待办**：按先后排好的事项。依次是明天就会枯萎的作物、今天能交的交付、钓一次鱼或进一趟山就能凑齐的交付、取出加工品并装满空着的设备、要加造的设备、去哪里弄材料（采石场哪几层、砍哪些树、在哪些树上放树液采集器）、空地种什么、畜舍还能养什么、今天能补的图鉴，最后是收获、浇水、喂食这些日常农活。要等 7:00 换日以后才能做的事（午夜后进别人家，或者今天剩下的时段钓不到的鱼）单独排在最后的“7:00 以后”一组。做完的事可以勾掉，勾选只对这份存档有效；读同一天稍后的存档时，清单重新开始。每一项都能跳到下面对应的部分，有位置的还能在地图上标出来。
- **交付**：修复祠堂、狐狸神社供奉和村长家交付目录三张清单，分成四个标签页。“今天可以交”是能整项交完的项目；“物品交付”是这季能凑齐的项目，附缺的东西从哪里来，能估算时附预计天数；“本季凑不齐”是缺的东西里有这季拿不到的项目；“留给交付的物品”是分给交付的物品，加工安排不会用到它们。
- **今日可收集**：图鉴里还没有、或交付还缺，今天又拿得到的东西。钓鱼每个钓点一张卡片，列出要钓的鱼和它在今天剩下各时段的上钩概率；其余按来源分组：这季野外长的山菜和虫子、长成的树上能收的树液、到过的采石场楼层能挖到的东西，以及农场里现有设备用库存原料就能做的加工品。
- **加工设备**：今天空着、已经做好或今天会做好的槽位各放什么。上面三个数字是今天放进去的原料数、做好后能卖的钱和比直接卖多赚的钱。每种设备一张卡片，列出槽位什么时候空出来、要放的原料和数量、做好能卖多少、直接卖多少。下面的“各原料的加工设备”每种原料一行，可以在下拉框里改选设备或不加工，选回推荐的设备就恢复默认。
- **加造设备**：按现在的数量，要排 7 天以上才做得完仓库里原料的设备。每张卡片列出等着加工的原料、每多一个槽位每天约多赚多少、新造或升级一台要的材料和库存够造几台，材料不够时附上去哪里弄。
- **空地和家畜**：“空地种植”列出农田范围里空着的格子可以种什么。“家畜”每种畜舍一张卡片，显示住了多少、交付要的畜产品该养哪种动物；没有空位时，列出要在树木建设订哪项改建或新建，以及要多少材料和金钱。
- **农场概况**：换季和稻草人提醒、可收获的作物、浇水和喂食等日常杂务、未来 7 天会成熟的作物、农田格子数和稻草人剩余天数。

每一组作物、每个稻草人、要砍的树和要放树液采集器的树都可以点“地图”，在弹出的地图窗口里标出对应的格子；树按棵计数。农场外面画的是整个村子，和农场一样从游戏的地图文件导出，所以农场外的树也找得到。缩小时显示一张村子全图，放大后再载入眼前这一块的清晰图。缩小到格子看不清时，标出的位置画成红色图钉。

午夜后的存档（00:00–06:59）还属于前一天。页面会提示离 07:00 换日还有几个小时，并按深夜的规则排今日待办，见下面的“午夜后”。

## 怎么算

### 交付

- 只算还没交完的项目。修复祠堂一次只能做一座，只列编号最小的一座。村长家交付目录在标志 12036 开启前不列。
- 背包和收纳箱里的物品按这个顺序分配：修复祠堂、本季的狐狸神社供奉、村长家交付目录、其他季节的供奉。先分给能整项交完的项目，剩下的再分给还没凑齐的项目。
- 顺序相同时，有品质要求的项目先分。每项先用刚好达到要求的品质，高品质的留给要求更高的项目。
- 缺的东西这季都有来源（田里的作物、这季能种的作物、钓得到的鱼、山菜、家畜、树木、设备或采石场）时，项目列在“物品交付”。有东西只在别的季节有，或者还没查到从哪里来，才列进“本季凑不齐”。
- 预计天数只在缺的东西都有确定日子时显示。田里正在长的作物按每格成熟的天数一格格累计到够数为止；今天剩下的时段里钓得到的鱼、这季野外长的山菜和农场里已有动物的产物算作今天就能拿到。这季钓得到、但今天剩下的时段都不上钩的鱼算 1 天；本季最后一晚算拿不到。

### 加工设备

- 要放的原料是分给交付后剩下的库存，加上今天成熟的作物（包括再生作物的后续收获）、还能收的枯萎作物和果树今天摇得下的果子，交付还缺的先留出来。家畜今天的产物不算。只算作物、水果、花卉、山菜和畜产品，价钱按普通品质算。
- 今天能放的槽位：空着的、产品已经做好的，以及今天结束前（午夜；午夜后的存档到 07:00 换日）做好的。一小时内先后做好的槽位算一轮，按最后一个做好的时间显示。
- 一个槽位放一批原料。在这些槽位里按比直接卖多赚的钱找总增益最高的放法（最小费用流），一种原料可以分到几种设备。加工后不比原料值钱的配方不放。
- 表里改选了设备的原料只放进所选的设备，选“不加工”就不放。推荐的设备是不改选时计划的选择；今天放不进的原料，推荐农场里已有设备中最值钱的配方，没有的话是能造、而且每个原料多赚 20 以上的设备。

### 加造设备

- 今天放完后剩下的原料排在各自推荐的设备上。一种设备正在做的、今天要放的和排队的原料加起来，按槽位数算要超过 7 天，就列进加造设备。
- 先建议把一级设备升级成“／改”，再建议直接新造“／改”，最后是新造一级设备。游戏里没有直接做“／改”的配方：升级配方要用掉一台一级设备，所以直接新造的材料是两个配方相加，先造一台一级设备，不摆出来就升级。这样一台的占地能有“／改”的槽位数。还没学会升级配方时只造一级设备；一级配方也没学会时，显示要学的祠堂能力。
- “每多 1 个槽位每天约多赚”取排队的原料里，一个槽位加工一整天多赚最多的那种。
- 能造几台按交付留出后的库存算。铁条这类在设备里做的材料不够时，也把它的原料（矿石、煤炭）算进去，但只往下算一层。

### 今日可收集

- 有没有登记看存档里的图鉴记录（`encyclopediaReleaseMap_`）。游戏图鉴本来就不列的物品（`ITEM_FEATURE_NOT_PUBLISH_ENCYCLOPEDIA`）只在交付缺时才列。交付还缺的数量和“物品交付”一致。
- 钓鱼：按 fishing.dat 每个钓点、本季、今天剩下的时段算，和钓点指南（`/guides/fishing-spots/`）用同一个算法：不用鱼饵时每次上钩钓到该鱼的机会，杂物不列。时段按 fishing.dat 写的 7–12、12–18、18–24、0–6 时，相邻时段概率相同时合在一起显示。钓点按要钓的鱼的种数排；每个钓点里交付缺的鱼在前，其余按概率从高到低。
- 野外：`naturaloccurrence.dat` 的山菜和昆虫生成组给出每种东西长在哪个季节（被埋起来的硬币四季都有，但要等第 2 章的标志 12902），采到的物品来自 `cropsharvest.dat`，由 `tools/extract-natural-occurrence.py` 导出。生成组没有写在哪张地图的哪里，所以页面只列季节。狐狸神社供奉里的山菜和这张表的季节全部一致。
- 树液：村里有长成的对应树。采石场：到过的楼层里有掉落。加工：农场里有这种设备，交付留出后的库存够做一份。
- 今日待办里合成一项“补图鉴”，只算图鉴还没有的；交付缺的东西已经在钓鱼、采集和交付的事项里。

### 材料从哪里来

- 采石场：按每层各种石头出现的权重和每种石头的掉落，算出每敲 100 块石头的期望数量，掉落相同的楼层合并成一段。只在到过的楼层里挑数量最多的一段（标志 21801–21812 记录到过第 10–120 层），一层都没有时列出最浅的一段并注明还没到过。
- 木材：按道具说明，木材来自栗子树、槲树和松树，好加工的木材来自柳杉，坚硬的木材来自桧木。按 `cropsharvest.dat`，长成的树用斧头砍倒出 12–18 个对应的木材。页面列出村里长成的树、还在长的树和手上的树种（树约 10 天长成）。木材的来源里还会提到村子西北边附身草丛里的树桩。
- 树液：树液采集器放在长成的对应树上，3 天收一次。
- 山菜和昆虫：按 `naturaloccurrence.dat` 的季节，见上面的“今日可收集”。
- 其他来源：田里的作物、这季能种的作物、钓鱼、家畜和设备配方。

### 午夜后

00:00 到 07:00 换日之前的存档按深夜算：

- 进不了别人家。村长家的交付目录在村长家里交，今天能交完的也排进“7:00 以后”。修复祠堂和狐狸神社在屋外，照常可以交。
- 钓鱼按 fishing.dat 的四个时段：7–12、12–18、18–24 和 0–7 时。0–7 时只有 6 种被诅咒的鱼和垃圾上钩，这几种鱼也只在这个时段上钩。只差这季白天的鱼的交付，钓鱼那一项排进“7:00 以后”。
- 山菜深夜也能采，只要还在原地。

### 空地种植

- 空地是农田范围里已耕待种和要重新翻耕的格子。
- 只列这季能长、能种在耕地或田垄上、剩下的天数里来得及成熟（下一季也能长的作物可以跨季）、种子在手上或这季有卖的作物。
- 交付还差的作物排在前面，其余按收益规划算出的每格利润排（扣掉种子钱，算上再生和加工）。加工只算农场里已有、而且不用加造的设备。

### 家畜

- 家畜每天的产量还没核实，页面不估算收益，只列交付要、但农场里还没有动物能产的畜产品和对应的动物（几个品种都产时取编号最小的一种）。
- 对应的畜舍没有空位时，页面建议树木建设的订单：先把最小的一座改建（4→8→12 个位置），都已是最大时在数量上限内新建一座。马厩要等第一座畜舍建好、收到木助的信后才能订（标志 550）。价格、材料和上限来自 construction.dat，位置数来自订单说明。

### 设置

每种原料改选的设备按存档里的玩家名保存在浏览器里（`localStorage` 键 `village-daily:settings:v1`）。今日待办里勾掉的事项也按玩家名保存（键 `village-daily:done:v1`），只对日期和时间都相同的存档有效。

## 农田范围

存档只记录耕过的格子，空着的耕地和田垄每晚约有一半会变回平地，所以存档本身说不清你有多少地。页面在浏览器里记住农田范围：

- 每次读取存档，所有耕地、田垄、水田和种着作物的格子会自动加入。
- 在地图上框选格子，可以手动加入或移出。只能选能耕作的地面，建筑、设施和地板下的格子会被跳过。
- 手动移出的格子以后不会再自动加入。
- 范围按存档里的玩家名分开保存（`localStorage` 键 `village-daily:farm-area:v1`）。浏览器禁止存储时，范围只在当前页面有效。

## 规则依据

以下规则用同一槽位连续五个存档核对：秋 28 日 07:00 和 00:00、冬 1 日 07:00 和 00:00、冬 2 日 07:00。

| 规则 | 存档里的证据 |
| --- | --- |
| 07:00 换日；浇水和喂食在换日时重置 | 冬 1 日浇过水的 381 格作物和喂过的 8 只动物，到冬 2 日 07:00 都变回没浇水、没喂。只有一株还没到结果季的桑树一直标着浇过水 |
| 浇过水的耕地和田垄上，作物每晚长 100 点 | 380 格全部 +100 |
| 栽培包和果树不用浇水，每晚长 100 点 | 全部 +100。冬天还在长的秋季栽培包都在秋天稻草人的范围内 |
| 下一季不能生长的田间作物在换季时枯萎 | 秋 28 日预测的芋头 50 格、芝麻 2 格，和冬 1 日枯萎的格子完全一致 |
| 稻草人让周围 5×5 格里同季节的作物继续生长 | 秋 28 日放下的秋天稻草人范围内有 24 格秋季栽培包，冬 1 日、冬 2 日都照常 +100 |
| 稻草人放下后每次换日计 1 天，到 28 天失效 | 存档里稻草人的 `days` 从 0 到 1、2 逐日增加；秋 28 日早上两个夏天稻草人是 `days` 28，并标记 `disable` |
| 稻草人失效时，范围内过季的田间作物枯萎 | 同一天早上地里的 40 格枯株全是夏季作物（黄瓜、蓝莓、玉米、毛豆），全部在这两个夏天稻草人的范围内 |
| 空着的耕地和田垄每晚约一半变回平地，无法预测 | 177 格耕地变回 89 格，188 格田垄变回 92 格；变与不变的格子数据相同；种着作物的格子不会变 |

另外几条来自游戏数据或站内已有资料：

- 成熟的毛豆换季后变成可收获的黄豆，是唯一在 `harvest_stages` 里有枯萎收获阶段的作物，不会被列进“最后一天不收就枯萎”。
- 果树只在 `perennial.bearing_seasons` 里的季节结果；温室限定的果树四季都列着。
- 稻草人的范围和时长来自道具说明（“对中心起算5×5格，可以发挥28天效果”），存档里的范围标记是 `PLACEMENT_EFFECT_RANGE_2`。失效的稻草人不会自己消失，要用斧头拆掉。
- 栽培包的道具说明写着“只在秋天生长”。页面把秋天以外、又不在秋天稻草人范围内的栽培包当作停止生长，不列进预测和提醒。
- 交付接受要求品质及以上的物品，没有期限。目录在标志 12036 开启后开放。
- 水田不用浇水。

## 还没核实

- 没浇水的田间作物：存档里所有在长的田间作物都浇过水，没有对照。预测按每天浇水计算。
- 下雨是否自动浇水、肥料对生长的影响、温室格子：存档里没有对应情况。
- 季节外的栽培包是枯萎还是等到秋天：存档里的栽培包都在稻草人范围内。页面不说成熟的栽培包会在换季时枯萎。
- 稻草人失效那次换日，作物会不会先长一天再枯萎：页面按不会计算，所以“还剩 N 天”和本季剩余天数的算法相同。
- 其他季节的狐狸神社供奉能不能在当季以外交：页面把它们和本季的一起列，排在最后。
- 附身草丛的树桩：玩家说那里有很多，但 `cropsplacement.dat` 在那张地图上没有摆放树桩，所以不知道有几个、每个出多少木材。附身草丛不在村子地图上，没法标出来。
- 家畜每天的产量和品质。
- 采石场的期望数量只算普通石头，不含矿脉房间和蜂巢。
- 山菜和昆虫长在哪里：`naturaloccurrence.dat` 只有生成组和季节，地图文件里也没有出现这些组的名字。
- 深夜时商店能不能买种子、树木建设能不能下订单、采石场能不能进：页面没有按时间调整这些事项。

## 代码位置

- `src/lib/saveDaily.ts`：从存档读出格子、设备、物品、交付进度、树木、畜舍、采石场进度、稻草人和图鉴记录。
- `src/data/dailyPayload.ts`：生成 `daily-data.json`，包括交付清单、设备配方、卖价、鱼的季节和各钓点的上钩概率、山菜和昆虫的季节、采石场掉落、畜产品和畜舍订单。
- `src/domain/dailyDigest.ts`：田里的每日规则，不依赖存档，测试用合成数据。
- `src/domain/dailyPlan.ts`：把交付（`dailyDeliveries`）、加工（`dailyProcessing`）、材料（`dailyMaterials`、`dailySources`）、种植（`dailyPlanting`）、家畜（`dailyLivestock`）、今日可收集（`dailyCollect`）和今日待办（`dailyActions`）串起来。
- `src/lib/dailyData.ts`：载入页面数据，保存设置；`src/lib/farmArea.ts`：农田范围的合并和存储。
- `src/components/daily/`：页面和农田地图（复用存档编辑器的 `MapCanvas`，农场外是 `public/maps/village/` 里的村子分块图，由 `tools/extract-village-art.py` 导出）。
- 用存档核对的测试在 `src/lib/saveDaily.test.ts` 和 `src/domain/dailyPlan.test.ts`，需要解密的存档样本（见 `tests/gamesave/README.md`），没有样本时自动跳过。
