# 卖掉家畜后的回礼

在构建 25640656（village.exe sha256 979aebe3…）上核对。只依据 `livestock.dat`、`letter.dat`、物品说明和 village.exe 的代码，没有实测回礼结果。

## 表结构

village.exe 把 `livestock.dat` 读成 `LivestockData`，字段按序列化顺序依次写入，`feature` 和 `dropItem` 是变长数组，所以后面字段的字节偏移随记录变化。`tools/extract-livestock-products.py` 按下面的顺序走：

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| 100 | `feature` 个数 | 后面每项 8 字节，记为 n |
| 104 + 8n | `isDailyUpdateDrop`、`dropNeedDay` | 各 4 字节 |
| 112 + 8n | `dropItem` 个数 | 后面每项 16 字节：物品 ID（u64）、`rate`、`needLoveRate`，记为 m |
| 116 + 8n + 16m + 100 | `itemID` | 3 个家畜物品 ID（各颜色），各 8 字节 |
| 紧接其后 | `sellingInfo` | `value`（u32），再接 3 个 `ItemInfo`：`id`（u64）、`probability`（u32）、`fixedValue`（u32） |

`sellingInfo` 的类型是 `SellingInfo { value; CFixArray<ItemInfo, 3> itemInfo; }`。例如鸡（记录 1）的 `sellingInfo` 在字节 280：`value` 3，鸡肉 40/1、鸟的羽毛 30/1、鸡的尾羽 30/0（概率/保底）。

另一种读法把 `value` 和上一项的 `fixedValue` 当作“数量”，得到“鸡肉 ×3，权重 40”。这种读法错位了一个字段，不对。

## 回礼计算

0x1402c5a70 遍历家畜列表，对已售出且 `growthID` 为 0（成年）的家畜调用 0x140117290 计算回礼，再把数量不为 0 的物品作为附件，用信件编号 6（`LETTER_ID_SELL_LIVESTOCK`，“家畜售出谢函”）寄出。幼畜的 `growthID` 指向成年家畜，不寄回礼。

0x140117290 的计算：

1. 剩余件数取 `value`。
2. 依次看 3 个 `ItemInfo`。`id` 为 0 的整项跳过，不给保底，也不参与抽取。其余每项先在结果里放 `fixedValue` 个；`probability` 大于 0 的加入抽取列表；剩余件数减去 `fixedValue`。
3. 剩余件数大于 0 时逐件抽取：用 0x1406808c0（MT19937，结果缩到 0 到总权重减 1）取随机数，加 1 后沿抽取列表累加 `probability`，取第一个累计值不小于它的物品，数量加 1。

所以每封信共 `value` 件（保底总数超过 `value` 时按保底给）。每抽一件，抽中某物品的概率是 `probability / 总权重`。羊的第 3 项物品 ID 为 0、概率 15，被跳过，抽取只在羔羊肉 55 和小动物的骨头 30 之间进行。

物品数量会按该物品数量的上下限截断，和狩猎证明报酬相同。“隔天寄到”来自鸡肉、牛肉、猪肉等物品说明，没有在代码里另行核对。

## 复查方法

在 .text 中找引用 `sellingInfo` 字段名的序列化函数（0x1400248f1），从类型描述符 0x140a37ba8 找到 `SellingInfo` 的序列化函数 0x140031c30，再在反汇编里找同时读取 `+0x218`（`value`）和 `+0x22c`（第一个 `fixedValue`）且调用 0x1406808c0 的函数。
