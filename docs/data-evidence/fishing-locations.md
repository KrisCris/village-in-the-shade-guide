## 玩家名称与内部鱼群表

`fishing.dat` 每条记录的字符串组第二项是水域配置名，而不是玩家名称。
用 `item.dat` 中单地点深夜鱼的繁体中文说明（字符串组索引 17），按物品数字 ID 反查 `fishing.dat` 的出现记录，得到下表。

例如物品 162020 的游戏中文说明为“深夜時可於瀑布釣魚處釣到。”，实际出现表只有 FISHING_ID_03。
显示名称仅将“村裡／山裡”整理为“村中／山中”，将“釣魚處”统一为“钓鱼点”；采石场沿用游戏用词。
提取器按上述引用连接生成名称，不按数字顺序硬配。原始配置名仍在名称的日文与别名数据中保留。

## 地图连接

`fishing.dat` 字节 24 引用 `mapgroundelement.dat` 的地面属性，依次为 25、26、28、27、29、30。
注意第三、第四条地面属性的编号与鱼群表顺序相反。
`mapgroundelement.dat` 的对应 u64 位为 24、25、27、26、28、29（从 0 起）。
`data/map_1_00.dat` 内 `data/map/map_0000_spr.ymwr.head` 的地形数据存在这些位。
字节 28 的 10001010 等引用的是 `gamevalue.dat` 中的钓获计数器，不是地图位置。

## 文案与运行表的差异

鲶鱼（160170）的说明提及岔路、瀑布、山里，但出现记录为 FISHING_ID_01、02、04，即岔路、村中、山中。
因此，名称采用多个单地点说明交叉验证；某条鱼的实际季节、时段和地点仍由出现表决定，不能从物品说明反推覆盖。
